## 最初怎样限定任务

用户要求完整核对飞书原题，在独立的 `interview-solution` 中实现一个简单、可解释、可测试的 Agent。学习网站只作只读参考，不修改文件、记录、模型配置或服务；真实模型与模拟演示的证据分开，不代为向公司提交。

实际使用过的子任务提示节选：

1. “三个工具 calculator(expression)（AST 白名单不可 eval，数值/长度/节点边界，拒绝非有限值），search(query)（明确 mock 本地小语料），read_docs(document_id)（固定文档 allowlist）。”用来限定工具能力和输入边界。
2. “输入 OpenAI形 dict，将 system 抽到 system，多 tool result 合并到一个 user content；将 function schemas 映射 input_schema。”这是早期 Messages 适配器任务，后来新增 Responses 为当前主线。
3. “只读审查……真实协议兼容、多轮工具消息配对、压缩、持久化并发、异常和题目覆盖。”用于在实现后检查需求与代码是否一致。
4. “围绕订单：稳定 operation_id 与 tool_call_id 区分，原子唯一约束+参数摘要+状态机……文档须明确设计边界。”用于准备第 4 题架构答案。

程序实际发给模型的系统提示在 `agent/runtime.py` 的 `SYSTEM_PROMPT` 中：按问题选择回答或工具，计算使用 calculator，search 只查本地模拟资料，错误时可以纠正，不编造工具成功。公开行动说明可保留；Responses 的不透明加密字段只用于协议续接，不解密或写入日志。

## 实现时的取舍

采用 Python 命令行、标准库 HTTP 和 SQLite、一个 JSON Schema 依赖。用完整轮次作为压缩单位，是为了容易保持工具请求与结果配对；采用提取式摘录，是为了让压缩规则可以直接阅读和验证。代价是摘录会丢失信息。

没有加入前端、FastAPI、向量数据库或生产级任务队列。这些不是本题跑通主循环的前提，先把循环、会话、工具和错误边界写清楚。双协议适配保留现状，本轮不再做额外抽象。

## 10 月 8 日：最初实现与模型接入

| 遇到的问题 | 原因与处理 |
|---|---|
| web 工具无法读取飞书 | 改用浏览器读取原题，核对实作要求及九道架构题 |
| 初次测试出现 14 项临时数据库清理错误 | SQLite 上下文管理器处理事务但不自动 close；补上显式关闭，当阶段 40 项测试通过 |
| 日志不可写使 ask 抛异常 | Trace 捕获写入故障，一次提示后继续，并加入回归 |

| 修改后测试夹具互相影响 | 不同错误子用例复用了同一 session 和 ID；改为独立会话 |
| 旧模型真实调用失败 | 首次请求失败，单次诊断确认 HTTP 502、上游拒绝访问；保留失败证据并停止 |

截至旧模型阶段，共有 2 次生成请求尝试和一次只读目录查询，当时真实验收尚未通过。这个结论只描述该阶段，不代表最终状态。

随后用户提供新凭据并要求切换 6.1。根据接入说明新增 ResponsesModel，通过官方文档核对函数调用及加密上下文续接，扩展到 54 项离线测试。截图 OCR 起初误读了凭据，导致认证拒绝；之后用不回显输入准确录入，密钥只以 DPAPI 密文保存，目录确认模型 ID 为 `gpt-6.1-sol`。

继续检查发现 reasoning item 的 status 可以为 null，修复后为 55 项离线测试。首轮正确凭据的真实验收完成了文本、追问和三工具执行，但汇总超过 40 秒超时。保留结果后，将该平台的配置显式调整为 90 秒，重新进行了一次验收，代码没有自动重试。

## 10 月 9 日：独立复查与两道架构材料

用户要求“认认真真的审查好面试题的内容，然后再审查一下我们实作的质量”，材料要丰富、易懂、不过度复杂。先只读核题、跑完原有 55 项测试，再并行检查协议、Runtime 和文档。用户确认第 4 题主答、第 5 题补充，采用精炼正文加详细讲解，并授权实施。

本轮任务提示的关键要求包括：“最小修复”“不要破坏 native replay”“不重构继承”“摘要按实际 size 淘汰”“两题共享 Agent 下单案例”“所有订单均为设计非已实现”。这些约束用于控制改动范围。

| 审查发现 | 本轮处理与回归 |
|---|---|
| 只有 commentary 的响应被判完成 | 新响应解析返回 `model_incomplete`；保留普通无 phase 回答和历史回放 |
| 旧 Messages 丢弃 thinking 后继续 | 明确返回 `model_unsupported_thinking`，文档限定兼容范围 |
| 摘要原始长度合格，转义后的总上下文仍超限 | 在完整轮次压缩后继续按实际序列化大小淘汰摘要，验证下一条短问仍可继续 |
| SQLite 启动或列表查询故障直接抛出 | 增加受控提示与退出/继续策略，损坏数据库不自动重建 |
| 空 `--ask` 误入交互模式 | 区分未传参数与空字符串，空输入由 Runtime 拒绝 |
| 旧协议、旧状态与新说明混在一起 | 跟读改为 Responses 主线，按阶段整理工作记录，修正真实验收命令和“重新加载”的表述 |
| 第 4 题 UNKNOWN 重试条件前后不一致 | 统一为先查询、有效幂等契约下同键重发，否则保留待确认 |
| 尚无第 5 题材料 | 补充业务事实、任务进度与会话记忆的归属，以及旧快照和恢复场景 |

修复后全部 64 项离线测试通过。使用相同 6.1 配置执行一次有界真实验收，6 项场景全部通过、8 次 HTTP 请求、零自动重试；新记录为 `live-smoke-gpt-6.1-sol-review-2026-10-09.json`，没有覆盖前一日记录。截至本轮真实验收，已记录的生成请求尝试累计为 23 次，目录查询另计。最终交付复现结果见验证说明。
